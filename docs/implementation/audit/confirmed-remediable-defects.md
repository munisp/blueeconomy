# Confirmed Remediable Defects and Deployment Blockers

> **Historical record — superseded for disposition.** This register records findings as they were confirmed during the source audit. The remediation status in `production-readiness-assessment-2026-08-13.md` is authoritative; several entries below were remediated and revalidated after this record was written. Missing S1–S6 business capabilities remain documented separately in `business-rule-coverage-matrix.md`.

| ID | Severity | Repository | Finding | Evidence | Disposition |
|---|---|---|---|---|---|
| BE-AUD-001 | High | `blueeconomy-maritime-evidence` | Concurrent identical `Create` calls can race after both observe no row; losing callers receive PostgreSQL unique-key errors instead of the retained package. This violates concurrent idempotency even though sequential replay is correct. | Deterministic real-PostgreSQL failure in `evidence-concurrent-idempotency-deterministic-before-fix.log`; `internal/evidence/store.go:25-80`; unique constraint in `db/migrations/0001_evidence.sql:5-8`. | Fix with atomic `INSERT ... ON CONFLICT DO NOTHING`, then lock/read/compare retained content; preserve one initial history row. Keep real-PostgreSQL concurrency regression. |
| BE-AUD-002 | Medium | `blueeconomy-credential-verification` | `--evidence` may resolve to the same path as `--credential`; successful verification then replaces the source credential with evidence. | `src/verify.ts:41-49`, `src/verify.ts:73-79`; no alias check in `parseConfiguration`; tests cover only missing credential and HTTPS JWKS. | Reject same canonical input/output path and add regression test. |
| BE-AUD-003 | Medium | `blueeconomy-security-operations` | `--evidence` may alias `--config`; after checks complete, atomic rename can replace the authoritative endpoint registry with evidence. | `cmd/integration-verifier/main.go:16-36`; `internal/verify/runner.go:168-186`. | Reject same canonical input/output path before loading/running and add regression coverage. |
| BE-AUD-004 | Medium | `blueeconomy-security-operations` | When redirects are allowed, the HTTP client accepts an arbitrary redirect target without reapplying the configured HTTPS requirement or approved-origin boundary. A configured authorization value can therefore be exposed to an unintended redirect target subject to client forwarding behavior, and the verifier can attest a response from a different destination. | `internal/verify/runner.go:101-109`; endpoint URL scheme is validated only before the request in `internal/verify/config.go:74-93`. | Validate every redirect target: enforce HTTPS when required, prohibit credentials, and require the original scheme/host unless an explicit allowlist is added. Add runtime redirect tests. |
| BE-AUD-005 | High deployment blocker | `blueeconomy-administration-service` | The service treats a caller-supplied `X-Blueeconomy-Authenticated-Subject` value as authenticated identity and performs no local authorization for decision, provisioning or activation. This is safe only behind a proven edge that strips and injects the header and enforces route roles; APISIX enforcement is not deployed or demonstrated. | `internal/admin/http.go:45-103`, `130-161`; local integration calls the service directly with arbitrary header values in `integration/run-local.sh:140-190`. | Do not expose service directly. Add cryptographically verified JWT middleware or mTLS-authenticated trusted-proxy enforcement plus explicit action-role checks; retain APISIX as defense in depth. Requires approved Ministry issuer/role policy. |
| BE-AUD-006 | High | `blueeconomy-administration-service` | Multi-role activation is not atomic. Group assignments are issued one by one; if a later assignment fails, earlier privileges remain while the request is recorded as `activation_failed`. There is no rollback or external-state reconciliation. | `internal/admin/keycloak.go:100-128`; failure recording in `internal/admin/http.go:111-125`. | Implement pre-state inspection plus compensating removal only for memberships added by the attempt, or move to a durable workflow with reconciliation and operator evidence. Requires real Keycloak failure-path integration testing. |
| BE-AUD-007 | High | `blueeconomy-administration-service` | A successful Keycloak invitation or role assignment followed by a PostgreSQL evidence-write failure leaves the database in `provisioning` or `activating` while the external side effect has occurred. Current claim methods cannot recover those states, and no reconciliation worker exists. | Explicit branches in `internal/admin/http.go:123-125` and `149-151`; claim predicates in `internal/admin/store.go:84-113`; no Temporal/outbox/reconciliation implementation. | Introduce a durable intent/outbox and reconciliation state machine before production. This is not safely solvable as a local retry patch without Ministry workflow and identity policy. |
| BE-AUD-008 | High repository-control gap | `blueeconomy-platform-gitops` / local Helm bundle | TigerBeetle, Mojaloop overlay and Sedona Helm source exists only in `/home/ubuntu/blueeconomy_core_services_helm`, which is not a Git repository and is absent from the private GitOps repository. This violates the explicit push-all-code requirement. | Local bundle inventory and GitOps comparison in the audit session; GitOps contains only source locks/base manifests. All four charts currently pass `helm lint`; render checks are retained in `core-helm-validation-before-versioning.log`. | Import reviewed source charts, examples, policies and guide into `blueeconomy-platform-gitops`; add deterministic Helm lint/render validation; commit and push. Do not claim deployment merely because templates are versioned. |
| BE-AUD-009 | Medium | `blueeconomy-administration-service` | Requested roles are validated after trimming a loop-local copy, but the original untrimmed slice is persisted. A value such as `" safety.telemetry.review "` passes the approved catalogue check, then fails Keycloak group lookup during activation and leaves the workflow failed. | `internal/admin/model.go:62-72`; persistence in `internal/admin/store.go:33-38`; exact map lookup in `internal/admin/keycloak.go:108-112`. | Normalize the role slice before validation/persistence or require exact canonical input. Add domain and PostgreSQL integration regression coverage. |
| BE-AUD-010 | High | All four Go repositories | Official `govulncheck` reports reachable vulnerabilities because modules build on Go 1.22.2; administration and maritime-evidence also use vulnerable `github.com/jackc/pgx/v5@v5.6.0` (GO-2026-5004, fixed in v5.9.2) and `golang.org/x/text@v0.14.0` (GO-2026-5970, fixed in v0.39.0). Scanner exit code is 3 for every module. | Retained reports under `dependency-audits/*-govulncheck.txt`; status table `dependency-audits/go-vulnerability-status.tsv`. The official database was updated 2026-08-11. | Raise the supported Go/toolchain baseline to a patched release, update pgx/transitives, run tests and real integrations with that toolchain, then require `govulncheck` in repository verification. |
